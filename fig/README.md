# ECG figures

This directory contains ECG's public SVG figures and editable Draw.io mirrors.
The 13 wiki figures follow one graph access through the single current
graph-adaptive record method: construction, layout selection, decoded future,
cache decision, real-record prefetch, native execution, state ownership, and
evidence boundaries.

The wiki and conference-paper collections remain independent:

- `fig/wiki` and `fig/wiki_src` are generated by
  `scripts/docs/generate_ecg_figures.py`;
- `fig/paper` and `fig/paper_src` retain their separate generator and layout.

Updating the wiki collection never rewrites paper files.

## Generated-mode contract

```text
fig/wiki/<page-slug>/<page-slug>-fNN-<topic>.svg
fig/wiki_src/<page-slug>/<page-slug>-fNN-<topic>.drawio
```

Run:

```bash
python3 scripts/docs/generate_ecg_figures.py
python3 scripts/docs/generate_ecg_figures.py --check
python3 scripts/docs/check_wiki_figures.py
```

Each figure uses a 1200 px canvas, live text of at least 16 px, accessible
title/description metadata, an opaque background, semantic arrow metadata,
and the `ecg-public/v1` file-format schema. That schema identifies generated
asset structure; it is not a research-method version.

SVG and Draw.io mirrors share canvas, labels, arrows, and deterministic
ordering. Connectors attach at boundaries, route around unrelated symbols,
and use the shared light/dark palette.

## Shared fixture and checked values

`fig/ecg-figure-fixture.json` defines the unchanged 32-vertex/34-record
fixture. The tracked access is outer vertex `u=8`, CSR position `j=18`,
property vertex `v=18`, next same-line position `j=22`, and semantic sequence
`s=19`.

| Quantity | Current value |
|---|---|
| layout | 4 bytes; ID 5; metadata 27; horizon 6; exponent 3; mantissa 23 |
| distance coding | `d=4`; `q=2<<23`; FINITE token `16777218` |
| metadata mask / record | `0x20000040` / `0x20000052` |
| ID mask | `0x1f` |
| deadline | `23` |
| prior A access | `s18`, distance 2, deadline 20 |
| victim snapshot at watermark 19 | A remaining 1/score 0; B remaining 4/score 1 |
| property address / line | `0x80000048` / `0x80000040` |
| property value | `1/128`, F32 `0x3c000000` |
| native raw P17 | `0x0000000020000052` |
| optional record address | base `0x60000000`; `RA=0x60000048` |

The 16-record A/B window contains no eligible new line at leads 8–15.
Required bytes not yet available produce `NOT_READY`, not a fabricated
no-candidate result.

The figure tests compile against `ecg_record.h` and
`ecg_record_runtime.h`. Precision probes compare numeric M/H/m settings rather
than named fixed formats. Graph edges, P17-to-I1 dependency, F9 result path,
and SVG/Draw.io parity are checked independently.

## Current implementation scope shown

- functional cache_sim uses the shared codec, victim rule, and one record-window
  selector with access-step timing;
- native gem5 uses custom-1 raw32/raw64 record loads, an explicit record-address
  property operand, retirement transport, replacement, and acknowledged
  LLC-only prefetch traffic;
- Sniper has strict current-path admission for all four mechanisms and both
  widths; it remains modeled corroboration, not native RISC-V timing;
- resident prediction payload is 67 logical bits per line, but the figures do
  not claim complete silicon area.

Native raw4/raw8 and all-mechanism qualifications, the sealed-input 24 MiB
4-byte transport/combined pair, and the wide real-Orkut production pair have
completed. Sniper's translated real-graph pairs also completed. No final-paper
campaign result is claimed.

Current builders retain the source graph and allocate a separate 32- or 64-bit
carrier plus sparse line-indexed scratch. Historical in-place/fixed-format
paths are not presented as current.

The Sniper guest software window is always 16 `uint64_t` words
(1,024 data bits), plus 1,024 index bits and 16 valid bits. Its separate
runtime word bank is `16 * 257` bits. Sniper updates are labeled
bounded-completion-corroboration; architectural retirement belongs only to the
native gem5 path.

## Conference-paper figure set

The paper files under `fig/paper` and `fig/paper_src` preserve their own
generator, layout, and historical scope. They are intentionally not modified
by the wiki command. Use their existing generator and validator only when
working on that separate collection.
